# ジョブメドレー 求人スカウト自動化システム

候補者の取り込み → 対象条件による絞り込み → LLMによる文面生成 → 媒体への送信 →
追客予約 → 返信の自動検知 → 週次・月次の返信率分析。

ビズリーチ向けに構築・運用されている参照実装からの移植であり、**その運用で実際に
踏んだ29件の障害とその真因** を構造で塞ぐことを設計の中心に置いている。
対応表は [`docs/incidents.md`](docs/incidents.md)。

---

## まず知っておくべきこと: 50個の未確定な座標

このシステムには **意図的に空欄のままにしてある値が50個ある。**

```bash
scout coordinates      # 未確定の座標を、ラダー段階別に・取得方法つきで一覧
```

送信APIのURL、DOMセレクタ、レジュメのキー名、媒体のenum実値、
エンドポイントごとの成功ステータス、受信箱の構造 — これらは
**実際にジョブメドレーにログインして観測しない限り知りようがない。**

指示書の一貫した方針は **「推測で埋めないこと」**。推測で埋めると、その推測が
そのまま送信内容と対象判定に出る。参照実装で「ご希望の◯◯業界」という虚偽が
生まれたのは、まさに写像を確定せずに埋めたからである。

**未確定は未完成ではなく、方針である。** 埋め方は
[`docs/ladder.md`](docs/ladder.md) に手順化してある。

### 未確定でも動くように作ってある

コマンドごとに必要な座標だけを要求するので、ラダーの各段でシステムは実際に動く。

```
現在実行可能: analytics, coordinates, generate, preflight
```

座標が足りないコマンドは **黙って0件で成功せず、明示的に停止する。**
何が足りないか・どう取得するかをエラーメッセージが述べる。

## 設計の3つの賭け

### 1. 未確定の座標は「欠損値」ではなく独立した型

```python
Coord[T] = T | Unresolved
```

`mypy strict` が `Coord[str]` を `str` の引数へ渡すことを **拒否する。**
実行時チェックではなく型検査が「推測で埋めない」を守る。
値を取り出す唯一の手段は `require(coord, used_by=...)` で、その例外メッセージは
「どこで詰まったか」と「どうやって埋めるか」の両方を含む。

`None` を使わないのは意図的である。`None` は「確認した結果 存在しなかった」という
正当な値であり (例: この媒体に2段階認証は無い)、それと「まだ確認していない」を
混同することが、まさに禁じられている推測にあたる。

### 2. 判定はすべて純粋関数。ブラウザとネットワークは取得と適用のみ

`pyproject.toml` の mypy 設定が `browser.*` だけを緩めているのは、その宣言である。
純粋コアは **認証情報ゼロで完全にテストできる**。

### 3. 沈黙は固有の終了コードを持つ異常状態

送信0件・生成0件・送信履歴の空・ページングカーソルの非前進は、いずれも
「イベントが無い」ではなく **検知される状態** として扱う。

> 最も危険な失敗は例外ではなく「静かなゼロ件」である。
> 参照実装では、認証切れで全APIが失敗しているのに **CIは緑のまま送信0件が続いた。**

## セットアップ

```bash
pip install -e '.[dev]'
python -m playwright install chromium
```

**手元に何もインストールできない運用にも対応している。** 段階1で人間の操作が要るのは
ログインそのものだけで、それは普段のブラウザでできる。開発者ツールの
「Copy as cURL」をシークレット `JOBMEDLEY_SESSION_CURL` に入れれば、残りは
GitHub Actions 側で完結する (`.github/workflows/recon.yml`)。手順は
`docs/ladder.md` 段階1の経路A。

環境変数 (**設定ファイルには決して書かない**, 12.7):

| 変数 | 用途 |
|---|---|
| `ANTHROPIC_API_KEY` | 文面生成 |
| `JOBMEDLEY_STORAGE_STATE_B64` | 保存セッション (情報量が多いので優先される) |
| `JOBMEDLEY_SESSION_CURL` | 普通のブラウザの Copy as cURL。**手元に何も入れずに済む経路** |
| `JOBMEDLEY_EMAIL` / `JOBMEDLEY_PASSWORD` | 自動ログイン (フォールバック) |
| `SCOUT_DRY_RUN` | 安全弁の上書き。**preflight が実効値と由来を印字する** |
| `SCOUT_STATE_LOSS_GUARD` | 同上 |

## 使い方

```bash
scout coordinates         # 未確定の座標を段階別に一覧
scout preflight           # 環境点検 + 安全弁の実効値を印字
scout session import       # 段階1: ブラウザの Copy as cURL からセッションを作る (標準入力)
scout session check        # シークレットの形式だけを確認する (媒体へ接続しない)
scout recon login          # 段階1の別経路: 手元で手動ログイン (常にヘッドフル)
scout recon verify-session # 段階1の合格条件: 保存セッションで入り直せるか
scout recon observe-login  # 段階1の座標を観測し、YAMLに貼れる形で印字
scout session export       # 合格したセッションを base64 で出力 (CIシークレット用)
scout recon capture-send   # 段階3: 送信を中断しつつ内部APIを特定
scout dryrun --limit 3    # 段階5: 送信直前まで通す
scout send                # 段階6以降: 本番送信 (二重の明示操作が必要)
```

## 検証

```bash
python -m ruff check . && python -m ruff format --check .
python -m mypy                 # strict。Coord[T] の誤用はここで落ちる
python -m pytest -q

python -m pytest tests/guardrails -v   # 規約違反のソース走査
python -m pytest tests/contract -v     # 送信契約 (ネットワーク不要)
```

> **`python -m` で起動すること。** ツール管理系が入れた `mypy` が PATH で優先されると
> pydantic が見えず、**全モデルが Any に落ちて検査が静かに無効化される。**
> それはこの設計の土台である `Coord[T]` の強制を丸ごと失うことを意味する。

### ガードレールテストが守っているもの

「破っても動いてしまう」規約を、レビューではなく機械で止める。

| 規約 | 破ったときに起きること |
|---|---|
| `networkidle` を待たない | 毎回30秒のタイムアウトを捨てる (5.3) |
| 実時刻は `clock.py` だけ | 営業日判定もコホートも冪等もテスト不能になる |
| `sleep` は `browser/waits.py` だけ | テストが実時間ぶん遅くなり、やがて誰も回さない |
| ステータス比較は `api/success.py` だけ | 成功しているのに失敗扱いになる (6.2) |
| 安全critical な設定に既定値を置かない | タイポで年齢上限が無言で消える (7.6) |

## 運用上の注意

- **送信は取り消せない。** dry_run の解除は二重の明示操作を要求する
- **送信APIには自動リトライを掛けない。** 親切なリトライは二重送信に直結する
- **予備実行は最後に足す。** 冪等性が本番で証明されてから (12.3)
- 利用規約と自動化ポリシーの確認記録は [`docs/compliance.md`](docs/compliance.md)
