# 落とし穴カタログ — 症状・真因・それを塞いでいる場所

指示書14章の29件に、**このリポジトリのどこがそれを防いでいるか** を対応づけたもの。

移植時のチェックリストとして使うほか、「このガードは何のためにあるのか」を後から
辿れるようにするのが目的である。**8.5 の教訓** — 除外や例外の理由を残さないと、
後から「抜けている」と誤って埋め戻される — をリポジトリ規模で適用したもの。

凡例: ⛔ = コードで構造的に塞いだ / ⚠️ = 検知して報告する / 📋 = ラダーの手順で防ぐ

## この表の使い方

新しいガードを足したら **ここに1行足すこと。** 逆に、ここに載っているガードを外す
提案が出たら、対応する症状が再現しないことを確認してからにする。

指示書14章の29件のうち、**このリポジトリで「構造的に塞いだ」と言えるのは⛔の行だけ**
である。📋 の行はラダーの手順に依存しており、手順を飛ばせば再現する。⚠️ の行は
検知するだけで、対処は人間が行う。
